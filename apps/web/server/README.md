# Services serveur

Seul point d'accès à `@ha/db` et aux adaptateurs depuis l'application : les composants n'appellent jamais Prisma directement (voir CLAUDE.md).

- `auth/` : Better Auth (`auth()`) sur le rôle plateforme, chargement du profil et contrôles d'accès (`acces.ts`), gardes Next (`gardes.ts` : `requireCompte`, `requireSession`, `requireSuperadmin`, `requireRole`, `requireCentreAccess`, `perimetreCourant`), limitation de débit.
- `services/` : une fonction par cas d'usage. Chaque fonction reçoit l'acteur (et le périmètre pour les listes), revérifie les droits, valide sa saisie avec Zod et lève `ErreurSaisie` ou `AccesRefuseError`.
- Tests d'intégration : `*.int.test.ts`, sur la base `DATABASE_URL_TEST` (voir ADR-003). Les services s'y exécutent sous `ha_app`, les jeux de données passent par `@ha/db/admin`. `isolation.int.test.ts` : une entrée par table ; une table nouvelle sans politique RLS le fait échouer.
- `audit/journal.ts` : journal d'audit (ADR-004). `withAudit(acteur, operation, evenement)` exécute l'opération et écrit la ligne dans la même transaction (si le journal échoue, l'opération est annulée). **Tout service qui lit ou modifie un dossier patient passe par `withAudit`** : ouvrir un dossier = une ligne `READ`, avec `patientId` renseigné. Les champs modifiés viennent de `differencesAuditees` (liste blanche du domaine) ; le NIR n'est jamais écrit en clair.
- `chiffrement.ts` : `base(acteur)`, seul accès des services aux données métier : client soumis à la RLS dans le contexte du client de l'acteur (ADR-016), qui chiffre les champs de `CHAMPS_CHIFFRES` (ADR-005). `enTransaction(acteur, …)` en est la version transactionnelle (`withAudit` passe par elle). `empreinteNir(nir)` : empreinte HMAC pour la recherche exacte et les doublons (ADR-006).
- `services/factures.ts` : facture préparée (ADR-014, ADR-015). `evaluerFactures` est le seul chemin de lecture, pour la fiche comme pour la file : les lignes et les contrôles se calculent à chaque affichage, rien n'est stocké.
- `services/patients.ts` : fiches patient (ADR-006). Les couvertures AMO et AMC sont lues et écrites directement sur leurs modèles, jamais par relation imbriquée (l'extension ne chiffre pas les écritures imbriquées). Le NIR ne figure jamais dans une URL : la recherche par NIR passe par une server action et renvoie l'empreinte.
- `documents.ts` : stockage des documents (ADR-011). `documents()` chiffre quel que soit l'adaptateur ; `DOCUMENTS_STOCKAGE=memoire` sélectionne le Fake hors production, sinon S3.
